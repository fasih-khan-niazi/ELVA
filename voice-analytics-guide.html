Voice Analytics — what each part means

Reference for the ELVA dashboard at Voice Analytics. Numbers come from your tenant’s stored VoiceSession and VoiceTurn data (and related endpoints), unless noted.

Time window (dropdown)

Chooses how far back to look for turn-level metrics and the volume chart. Presets range from 1 hour through Lifetime (all stored history for your tenant).

How it degrades

  • Too narrow: Old calls fall outside the window — KPIs show dashes or zeros while “Total sessions” (below) can still look high.
  • Very wide / Lifetime: Chart buckets get coarser (e.g. weekly for lifetime) so fine-grained spikes are smoothed; first load can be slower with huge history.

How to make it better

  • Pick the smallest window that includes the calls you care about for latency/SLO; use Lifetime when you want all-time rollups.
  • Ensure voice traffic actually creates turns (speech → AI → reply) so the window has data to aggregate.

Top KPI row

MetricWhat it isDegrades when…Improvements
Active calls Calls with session status in progress right now. Always zero if no live call; not “calls today.” Treat as live concurrency. For “calls today” use session lists or future daily counters.
Total turns Count of VoiceTurn rows in the selected window (speech/response exchanges). Zero if no turns in window, or turns never persisted. Confirm webhooks hit the orchestrator path that writes VoiceTurn; widen the window or use Lifetime.
Phone / web Split of those turns by the session’s channel. Skewed if channel not set correctly on session. Ensure VoiceSession.channel is set when creating the session.
SLO compliance Share of turns with sloOk true (latency within the configured turn SLO). Shown as “—” when there are no turns; misleading if sample is tiny. More traffic; tune SLO targets to match product/infra reality.
Error rate Share of turns that stored a non-empty error field. “—” with no turns; may miss errors only logged elsewhere. Ensure error paths call persistErrorTurn so failures become rows.

Latency row (P50 / P90 / P99 / Avg / Min / Max)

Statistics over latencyMs on turns in the window. Compared to the SLO target card (product ceiling from config, not a live measurement).

How it degrades

  • No turns → dashes; percentiles need enough samples to be stable.
  • Outliers and cold starts move Max and P99 more than P50.

How to make it better

  • Optimize AI/STT/TTS timeouts and regional deployment; track regressions by release.

Turn volume & latency (chart)

Time buckets with turn counts, average latency in the bucket, errors, and call start/end events where applicable. Bucket size depends on window length (finer for short windows, coarser for long ones).

How it degrades

  • Empty if no activity in range; sparse traffic shows as isolated bars.
  • Long windows compress detail into coarse buckets.

Historical stats row (Total sessions, Completed, Failed, Endpoints)

Mostly all-time-ish tenant totals from sessions and endpoints — not constrained by the dropdown the same way the turn metrics are.

How it degrades

  • Can look “healthy” while the windowed KPIs are empty — different time semantics.

How to make it better

  • Align expectations: use the subtitle/range copy on the page for rolling windows vs lifetime.

Call end reasons

Breakdown by endReason on sessions where it exists (goodbye, hangup, timeouts, etc.).

How it degrades

  • Hidden or sparse if lifecycle hooks don’t set endReason reliably.

Alerts

Rule-based notices from the same snapshot as metrics (SLO, error rate, latency) plus AI service health from the orchestrator probe.

How it degrades

  • Few turns → fewer statistically meaningful alerts; health probe can lag real outages.
